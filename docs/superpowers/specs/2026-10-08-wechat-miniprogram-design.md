# 微信小程序版本设计说明

## 目标

在当前个人知识库项目中新增微信原生小程序客户端，视觉与信息架构遵循 Figma Make 原型，同时只接入现有 Go 网关真实支持的能力。

## 页面结构

1. **问答对答**：知识库选择器、对话消息、流式回答、引用溯源、停止生成。
2. **知识库体系**：统计概览、搜索、来源分组卡片、进入问答。
3. **原资料操作**：搜索与筛选、服务端路径摄入、重新载入、按来源删除。
4. **我的空间**：服务状态、向量库与模型信息、片段和来源统计、接口地址设置。

四个页面共享自定义顶部栏和底部导航。页面使用微信原生 WXML/WXSS/JavaScript，不引入组件库。

## 数据映射

- `GET /api/health`：服务在线状态。
- `GET /api/config`：模型、向量接口和向量库信息。
- `GET /api/stats`：知识片段总数。
- `GET /api/chunks`：来源分组、资料列表与搜索。
- `POST /api/chat/stream`：问答流式输出及引用。
- `POST /api/ingest`：服务端文件或目录路径摄入。
- `DELETE /api/chunks?source=`：删除来源。

当前后端没有多知识库、客户端文件上传、在线编辑、重新索引、登录与用量统计接口。对应入口保留原型视觉，但点击后明确提示需要后端支持，不展示伪造成功状态。

## 视觉系统

- 主色为墨绿色 `#2BA58F`，深色强调为 `#10192D`。
- 页面背景为 `#F5F7F8`，卡片使用白色、细边框和轻阴影。
- 采用 24rpx 至 32rpx 圆角、紧凑统计卡、固定底部导航和安全区适配。
- 自定义顶部栏读取微信胶囊位置，避免遮挡系统菜单。
- 动效只用于加载、消息出现和按钮反馈，并尊重系统减少动态效果设置。

## 状态与错误

- 首次进入并行读取健康、配置、统计和片段。
- 网络失败展示明确错误与重试入口，不自动回退到 Mock 数据。
- 问答支持取消请求；流式解析错误保留已接收内容并显示错误提示。
- 删除来源必须经过 `wx.showModal` 二次确认。
- API 地址保存在本地存储，开发工具默认使用 `http://127.0.0.1:8080`。

## 验证

- 使用 Node 内置测试运行 SSE 分块解析、UTF-8 边界、来源聚合、搜索与字节格式化测试。
- 使用 `node --check` 校验全部 JavaScript 文件。
- 解析所有 JSON 配置文件并检查页面文件集合完整。
- 运行现有 `go test ./...`，确认新增静态客户端不影响后端。
