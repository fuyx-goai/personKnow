## 1. 业务背景

### 1.1 行业背景

个人知识库正在从“文件收藏”演进为“可检索、可问答、可追溯”的知识工作台。用户不仅需要保存 PDF、Office 文档和文本资料，还希望通过 RAG 在指定资料范围内快速获得有引用依据的回答。

现有项目已经具备单知识库摄入、向量检索、流式问答、Web 页面和微信小程序外壳，但数据仍以单用户、单向量空间组织，无法支撑原型中的多知识库、文件全生命周期、账号隔离和用量统计。

本版本以 Figma 原型为唯一界面与交互基准，补齐 Go 后端、持久化、异步任务和账号体系，使页面中展示的功能全部由真实 API 支持。

### 1.2 问题陈述

- 当多名用户使用同一服务时，用户无法隔离各自的私有文件和问答记录，导致数据安全边界不成立。
- 当用户维护不同主题资料时，用户无法按知识库组织、公开或筛选内容，导致检索范围不可控。
- 当文件内容变化时，用户无法在线编辑解析文本并安全重新索引，导致问答结果与资料版本不一致。
- 当上传、向量化和问答持续消耗资源时，用户无法查看或约束容量与 Token，导致成本不可预测。

### 1.3 解决思路

构建微信登录、多用户隔离的模块化单体：PostgreSQL 保存业务与审计数据，本地目录保存原文件和编辑文本，Mem/Milvus 保存可过滤向量，后台 Worker 负责解析与索引。微信小程序和 Web 严格映射原型的问答、知识库、原资料和我的空间四个入口。

## 3. 产品定位与目标

### 3.1 一句话定位

> 个人知识库是一款面向需要整理专业资料的知识工作者的多端 RAG 应用，帮助他们安全管理文件并获得可溯源的知识问答。

### 3.2 目标用户画像

- **主要用户**：25–45 岁的研发、产品、研究与投资从业者，长期积累 PDF、Office 和 Markdown 资料，核心诉求是分类管理、精准检索和移动端快速问答。
- **次要用户**：被分享公开知识库的协作者，核心诉求是只读浏览并基于可信来源问答。

### 3.3 成功指标

- 首版支持约 100 名注册用户和 10 个并发问答。
- 七类文件上传、解析、编辑和重新索引成功率达到 95% 以上。
- 私有资源越权访问自动化测试覆盖率达到 100%。
- 所有关键写操作均生成可检索审计记录。
- 容量与 Token 汇总和明细流水保持一致。

## 4. 用户角色与权限

| 角色 | 描述 | 核心操作 | 受限操作 |
|------|------|---------|---------|
| 知识库所有者 | 创建并管理自己知识库的登录用户 | 创建、编辑、上传、索引、删除、问答、查看用量 | 不能操作他人的私有库或修改他人的公开库 |
| 公开库访问者 | 已登录并访问他人公开库的用户 | 只读查看、基于公开库问答 | 不能编辑、上传、重新索引或删除 |
| 未登录访客 | 没有有效会话的客户端 | 查看健康状态、发起登录 | 不能访问知识库、文件、问答和用量 |

系统不设置管理员角色。权限思维导图见 `diagrams.draft.md`。

## 5. 功能需求

### 5.1 账号与多端登录

#### 功能描述

小程序通过微信 `code2session` 登录；Web 创建短期二维码票据，由已登录小程序确认后登录同一账号。

#### 用户故事

- 作为小程序用户，我希望用微信身份快速登录，以便访问自己的知识库。
- 作为 Web 用户，我希望用小程序扫码确认，以便在电脑端继续使用同一账号。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-01-001 | 微信 code 只能使用一次，服务端换取 OpenID 后签发访问与刷新令牌 | P0 | 不记录 code |
| F-01-002 | Web 登录票据 5 分钟过期，只允许确认一次 | P0 | 轮询获取状态 |
| F-01-003 | 退出登录立即撤销当前刷新会话 | P0 | 访问令牌短期有效 |
| F-01-004 | 所有受保护 API 从令牌取得用户身份，禁止客户端指定 owner | P0 | 防越权 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 微信 code 无效 | 返回 `WECHAT_LOGIN_FAILED`，允许重新获取 code |
| 二维码过期 | Web 刷新二维码，小程序不得继续确认 |
| 会话撤销 | 返回 401，客户端清理本地会话并重新登录 |

#### 原型说明

“我的空间”展示当前微信用户资料；Web 未登录态展示扫码入口，不新增邮箱密码页面。

### 5.2 多知识库

#### 功能描述

用户可创建多个知识库，设置名称、分类、描述及私有/公开状态，并查看文件数、容量和 Token 统计。

#### 用户故事

- 作为所有者，我希望按主题建立知识库，以便控制检索范围。
- 作为访问者，我希望只读使用公开库，以便问答但不影响原内容。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-02-001 | 支持创建、查询、修改和删除知识库 | P0 | 删除异步执行 |
| F-02-002 | 支持私有与公开状态 | P0 | 公开仅限登录用户读取 |
| F-02-003 | 列表展示文件数、容量、Token 和分类标签 | P0 | 对应原型卡片 |
| F-02-004 | 问答页可选择单库或全域模式 | P0 | 全域含自己的库和公开库 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 名称为空或超长 | 返回字段级校验错误 |
| 访问私有库 | 返回 404，避免泄露资源存在性 |
| 删除处理中 | 禁止新增文件和问答，展示处理中状态 |

#### 原型说明

严格保留“专属知识库”标题、统计卡、分类筛选、新建知识库、资料管理和进入问答入口。

### 5.3 原资料全生命周期

#### 功能描述

支持 PDF、DOCX、Markdown、TXT、HTML、CSV、PPTX，单文件最大 50 MB。原文件永久保留，解析或编辑文本以版本保存并参与索引。

#### 用户故事

- 作为所有者，我希望上传并查看解析状态，以便确认资料可用。
- 作为所有者，我希望编辑解析文本或重命名，以便修正内容而不破坏原文件。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-03-001 | 上传前校验权限、格式、签名、大小和容量 | P0 | Multipart |
| F-03-002 | 保存原文件、解析文本、编辑文本版本和 SHA-256 | P0 | UUID 实际路径 |
| F-03-003 | 支持搜索、知识库筛选和状态筛选 | P0 | 对应操作台 |
| F-03-004 | 支持修改展示名称、标签和解析文本 | P0 | 修改内容后可索引 |
| F-03-005 | 支持彻底删除文件及其向量 | P0 | 二次确认、异步清理 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 文件超过 50 MB | 上传前后均拒绝，不计入容量 |
| 格式伪造 | 文件签名不匹配时拒绝并记录安全日志 |
| 解析失败 | 保留原文件，状态标记失败并允许重试 |
| 容量不足 | 返回 `STORAGE_QUOTA_EXCEEDED` |

#### 原型说明

严格保留“原资料文件操作台”、上传按钮、库筛选、文件卡片、状态标签、在线编辑、重新索引和删除入口。

### 5.4 异步重新索引

#### 功能描述

PostgreSQL 持久化索引任务，Worker 负责解析、切块、Embedding 和向量版本切换。

#### 用户故事

- 作为所有者，我希望重新索引期间仍能问答，以便服务不中断。
- 作为所有者，我希望看到任务进度和错误，以便重试失败任务。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-04-001 | 任务状态包含排队、处理、已就绪、失败、取消 | P0 | 持久化状态机 |
| F-04-002 | 使用数据库行锁领取任务并支持服务重启恢复 | P0 | 单实例无需 Redis |
| F-04-003 | 新版本全部写入成功后才切换有效版本 | P0 | 失败保留旧版本 |
| F-04-004 | 自动重试最多 3 次，失败后可手动重试 | P0 | 指数退避 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| Embedding 服务超时 | 任务重试并记录阶段和错误分类 |
| Token 额度不足 | 任务失败为配额错误，不继续调用模型 |
| 服务重启 | 回收超时任务并重新排队 |

#### 原型说明

文件状态标签展示任务状态；重新索引按钮在活跃任务期间禁用。

### 5.5 可溯源问答

#### 功能描述

支持指定知识库和全域混合检索，通过 SSE 返回流式回答、引用来源、模型与 Token 数。

#### 用户故事

- 作为用户，我希望限定目标库，以便获得更相关的回答。
- 作为用户，我希望查看原资料依据，以便验证回答可信度。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-05-001 | 创建与查询问答历史 | P0 | 用户隔离 |
| F-05-002 | SSE 流式输出回答并支持中断 | P0 | 记录实际用量 |
| F-05-003 | 引用包含文件、章节/页码、相似度 | P0 | 对应原型来源卡片 |
| F-05-004 | 检索过滤由服务端根据权限生成 | P0 | 禁止客户端绕过 |
| F-05-005 | 全域检索包含自己的库和他人的公开库 | P0 | 不含他人私有库 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| Token 额度不足 | 模型调用前返回 `TOKEN_QUOTA_EXCEEDED` |
| SSE 中断 | 保留已生成内容，消息标记 `interrupted` |
| 无可用片段 | 明确告知未在目标资料中找到依据 |

#### 原型说明

严格保留知识库选择、历史记录、新建问答、来源溯源、模型和 Token 展示。

### 5.6 用量、配额与日志

#### 功能描述

默认套餐为 Personal Pro，提供 5 GB 存储和每月 2,000,000 Tokens，并记录不可变用量流水、业务审计和结构化运行日志。

#### 用户故事

- 作为用户，我希望查看容量与 Token，以便控制使用成本。
- 作为用户，我希望关键操作可追踪，以便定位误操作和失败原因。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-06-001 | 统计存储、Embedding、问答输入与输出 Token | P0 | UTC 自然月 |
| F-06-002 | 并发操作下以事务和行锁执行配额校验 | P0 | 防止超卖 |
| F-06-003 | 记录登录、知识库和文件关键操作审计 | P0 | 保留 180 天 |
| F-06-004 | JSON 日志记录 request_id、耗时、状态和错误分类 | P0 | 不记录敏感正文 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 汇总与流水不一致 | 定时重算并生成告警日志 |
| 日志写入失败 | 不阻塞主业务，写入标准错误并告警 |
| 审计查询越权 | 仅返回当前用户自己的记录 |

#### 原型说明

“我的空间”按原型展示套餐、容量进度、Token、知识库数、文件数与退出登录。

### 5.7 RAG 检索微调与账号安全

#### 功能描述

“我的空间”三个页签均提供真实功能。RAG 检索微调按知识库保存切块与召回参数；账号与安全用于管理当前用户的微信资料和登录设备会话。

#### 用户故事

- 作为知识库所有者，我希望调整切块和召回参数，以便针对不同资料优化检索效果。
- 作为登录用户，我希望查看并撤销设备会话，以便保护账号安全。

#### 详细需求

| 需求ID | 需求描述 | 优先级 | 备注 |
|--------|---------|--------|------|
| F-07-001 | 每个知识库支持配置 `chunk_size`、`chunk_overlap`、`top_k` 和 `similarity_threshold` | P0 | 提供安全默认值与范围校验 |
| F-07-002 | 修改切块参数时明确提示需要重新索引，并创建库级批量重建任务 | P0 | 召回参数立即生效 |
| F-07-003 | 展示当前登录设备和其他有效刷新会话 | P0 | 不展示令牌和完整 IP |
| F-07-004 | 支持退出单个设备和退出全部其他设备 | P0 | 当前会话可单独退出 |
| F-07-005 | 支持从微信重新同步昵称和头像 | P1 | 不允许修改 OpenID 映射 |

#### 参数范围

| 参数 | 默认值 | 允许范围 | 生效方式 |
|------|--------|----------|----------|
| `chunk_size` | 800 | 200–2000 | 重新索引后生效 |
| `chunk_overlap` | 100 | 0–500，且小于 `chunk_size` | 重新索引后生效 |
| `top_k` | 5 | 1–20 | 下一次问答立即生效 |
| `similarity_threshold` | 0.30 | 0–1 | 下一次问答立即生效 |

#### 异常场景处理

| 场景 | 处理方式 |
|------|---------|
| 非所有者修改公开库参数 | 返回 403，不创建任务 |
| 参数组合非法 | 返回字段级错误和合法范围 |
| 库内已有活跃重建任务 | 返回现有任务，不重复创建 |
| 撤销当前会话 | 返回成功后客户端立即清理登录态 |

#### 原型说明

严格保留“容量与用量 / RAG检索微调 / 账号与安全”三个页签；不新增独立底部页面。

## 7. 业务流程概述

核心流程：用户通过微信登录；创建知识库；上传文件后立即获得异步任务状态；Worker 解析并建立可版本化索引；用户选择目标知识库进行流式问答并查看引用；系统同步记录容量、Token 和审计信息。

异常流程：配额不足在产生外部成本前拒绝；解析或向量化失败保留原文件及旧索引；服务重启恢复超时任务；越权访问统一返回不可见结果。详细图表见 `diagrams.draft.md`。

## 8. 名词解释

| 术语 | 定义 |
|------|------|
| RAG | 检索增强生成，通过检索资料片段辅助模型回答 |
| Chunk | 文档切分后用于检索的片段 |
| Content Version | 文档解析或编辑文本的不可变版本 |
| Active Version | 当前用于检索的已完整索引版本 |
| 全域检索 | 检索用户自己的所有知识库和其他用户的公开库 |
